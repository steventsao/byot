# BYOT 1.0.36 — Session list says "Connecting" while it waits

One new TestFlight item has arrived since 1.0.35, and this release answers it. The other 72 are recorded in earlier releases. Builds on 1.0.35 (`8ed7c65`, main).

## TestFlight feedback

| Feedback | Build | Disposition |
| --- | --- | --- |
| `AJd8dKpVdvbuffcbZ2FQRa0` (2026-10-19, "Why status unavailable?"; every row on the Macbook server read "Status unavailable", 51 s after launch) | 1.0.35 (`75839cb4`) | Fixed: rows say "Connecting" until the server answers. |

## What changed

| Area | Change |
| --- | --- |
| Session list rows (`OpenCodeProjectSessionsView.swift`, `OpenCodeConnectedView.swift`) | A row drew "Status unavailable" whenever its project had no status map. That covered three cases: a saved list shown at launch while byot reaches the server, a project still loading, and a server that answered with an error. The first two are the common ones. A tailnet computer that is asleep can hold the first request until URLSession's default 60 s timeout (the probe sets none), so for up to a minute the screen showed saved sessions, every row "Status unavailable", and nothing else on screen: the only "Refreshing sessions" row sits below the list. Rows now say "Connecting", with the same glyph and word as the conversation header (1.0.33, `AEk0EYWkKW0QGxg8A34z3r0`), until the project answers. While the offline notice ("Showing sessions saved …") is up, rows show no status, because the notice already says the server can't be reached. "Status unavailable" now appears only where the server returned an error, and that project's banner gives the reason. |
| Session browser store (`OpenCodeSessionBrowserStore.swift`) | New `pendingStatusIDs`: the listed sessions whose project has neither statuses nor an error, minus any that another project answered for. |
| Strings | None new. "Connecting" and "Status unavailable" already have Simplified Chinese. |

The routes were checked first, and they are not the cause. `GET /api/session/active` answers `{"data":{}}` on OpenCode 2.0.32 and on 2.1.0 (released 2026-10-20), and the two versions' openapi path lists are identical (119 paths).

## Not covered

- No rendering check of the row in the "Connecting" state. The label is the one session rows already draw for a known status, and "Connecting" is shorter than "Status unavailable".
- The 60 s wait before the offline notice is unchanged. A shorter probe timeout would bring the notice up sooner. It was left out because a slow server on mobile data could then be called offline when it isn't.
- Which of the three cases the reporter hit can't be told from the screenshot alone. Uptime and the missing top notice point to the first.
