# 1.0.31 signing checklist

1.0.31 adds app extension targets. Simulator builds and tests don't need
anything below, because the test helper builds with `CODE_SIGNING_ALLOWED=NO`.
An App Store archive does need all of it. Nothing here has been registered yet;
do it in the Apple Developer portal (team `449BD89VDV`) before running
`scripts/asc-build-testflight.sh`.

## BYOTWidgets: home-screen widget, Live Activity, Dynamic Island (#89)

| Item | Value |
| --- | --- |
| Target | `BYOTWidgets` (`project.yml`), embedded in `byot.app/PlugIns/BYOTWidgets.appex` |
| Bundle ID to register | `com.steventsao.byot.widgets` (explicit App ID) |
| App Group to create | `group.com.steventsao.byot` |
| Enable App Groups on | `com.steventsao.byot` **and** `com.steventsao.byot.widgets`, both assigned `group.com.steventsao.byot` |
| App entitlements | `Sources/BYOT.entitlements`: `aps-environment` (existing) and `com.apple.security.application-groups = [group.com.steventsao.byot]` (new) |
| Extension entitlements | `Widgets/BYOTWidgets.entitlements`: `com.apple.security.application-groups = [group.com.steventsao.byot]` |
| App Info.plist | `NSSupportsLiveActivities = YES` (no entitlement or capability needed for local Live Activities) |
| Push capability | None new. Live Activities are started and updated by the app, not by push, so there is no `pushType` and no ActivityKit push token. |

With automatic signing and `-allowProvisioningUpdates`, Xcode can usually
create the App ID and profiles and enable the App Group itself, as long as the
group already exists in the portal. Registering by hand first avoids a failed
archive.

### Required release-script change

`scripts/asc-build-testflight.sh` passes
`--xcodebuild-flag=PRODUCT_BUNDLE_IDENTIFIER="$BYOT_BUNDLE_ID"` to the archive.
A build setting given on the xcodebuild command line applies to **every**
target, so the widget extension would also be stamped `com.steventsao.byot`.
Its identifier must begin with the app's, so the archive (or App Store
validation) will fail. Before archiving with the widget, remove that flag
(`project.yml` already sets each target's bundle ID), or rename the variable the
flag sets. This lane did not edit the release script.

The extension's `CFBundleShortVersionString` / `CFBundleVersion` come from the
project-level `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`, as the app's do.
After `asc xcode version edit`, check that the archived `BYOTWidgets.appex`
has the same version and build as the app. App Store Connect rejects a
mismatch.

### Shipping without the widget

If signing isn't ready, the app still works without the extension:

1. In `project.yml`, delete the `- target: BYOTWidgets` entry under the `BYOT`
   target's `dependencies` (the `BYOTWidgets` target can stay; nothing builds it
   unless something depends on it).
2. Remove the `com.apple.security.application-groups` key from
   `Sources/BYOT.entitlements`, unless the share extension (below) still ships.
   It uses the same group.
3. Run `xcodegen generate`.

When the appex is missing, the app hides the Live Activities setting and never
starts an activity (`BYOTLiveActivityController.isWidgetExtensionEmbedded`).
The widget snapshot still gets written to a suite that nothing reads, which does
no harm.

## What testers should check on device

- **Live Activity.** Send a prompt and lock the phone: the Lock Screen shows the
  session, the current tool (for example "Edit file · LoginView.swift"), and an
  elapsed timer. Trigger a permission and it turns orange with "Approval
  needed". It ends as "Turn complete", "Turn failed", or "Turn stopped", then
  clears after about 15 minutes. Tap it to open that session.
- **Dynamic Island** (iPhone 14 Pro and later). While byot is in the
  background, the compact view shows a phase icon and the timer, or "Review"
  when approval is needed. Long-press to expand it for the title, status, and a
  Review button.
- **Leaving a turn running.** Go back to the session list while a turn runs.
  The activity stays up, and within about 15 seconds of the turn ending, the
  list's status polling finishes it.
- **Home Screen widget** (small, medium, and large) and the Lock Screen widgets
  (circular, rectangular, inline). They show sessions that need you (waiting
  approvals or questions, failed turns) and the number running, as of byot's
  last refresh. After 30 minutes without a refresh they say "May be out of
  date" / "Open byot to refresh". Tapping a row opens that session.
- **The switch.** About → Live Activities off ends all current activities.

## App Intents: Siri, Shortcuts, and App Shortcuts (#91)

| Item | Value |
| --- | --- |
| Target | None new. The intents are compiled into the `BYOT` app target (`Sources/BYOTIntents.swift`, `Sources/BYOTIntentEntities.swift`, `Sources/BYOTIntentService.swift`). |
| Bundle IDs to register | None |
| Capabilities / entitlements | None. App Intents and App Shortcuts don't use the SiriKit `com.apple.developer.siri` entitlement, so don't turn on the Siri capability for them. |
| Info.plist | No new keys. Xcode's App Intents metadata step writes `byot.app/Metadata.appintents` at build time. |

The intents work the same whether or not the `BYOTWidgets` extension ships.
After a session starts from Siri, the app's own process writes the widget
snapshot. Without the App Group, that write just stays private to the app.

### What testers should check on device

- **Ask OpenCode.** Say "Ask OpenCode in byot", or run it from Shortcuts or
  Spotlight. Siri asks what OpenCode should do. It uses the server byot last
  showed, and that server's configured working directory (or its only project;
  v1's catch-all "global" project at `/` is never offered or picked). When
  there are several projects, it asks which one. It needs an unlocked
  iPhone because it acts on your machine. Siri should answer "Sent. OpenCode is
  working in <project> on <server>." The session then shows as running in the
  widget, and new sessions use the model, agent and variant last picked on that
  server. "Ask OpenCode on <server> in byot" picks a server by name. Check that
  this phrase shows up after you add or rename a server.
- **Check sessions needing attention.** Say "What needs me in byot". Siri
  names up to three sessions waiting for approval or an answer, or that
  failed, counts the rest and the running ones, and names any server it
  couldn't reach. A card lists the sessions. This one also works from the Lock
  Screen, like the widget.
- **Open Session.** In Shortcuts, add "Open Session" and pick from recent
  sessions, or chain it after Ask OpenCode or Check Sessions. Running it opens
  byot on that session. A removed server shows the same alert as a widget tap.
- **About → Siri & Shortcuts** opens byot's page in the Shortcuts app.

## BYOTShare: share extension (#92)

| Item | Value |
| --- | --- |
| Target | `BYOTShare` (`project.yml`), embedded in `byot.app/PlugIns/BYOTShare.appex` |
| Bundle ID to register | `com.steventsao.byot.share` (explicit App ID) |
| App Group | The same `group.com.steventsao.byot` the widgets use. Enable App Groups on `com.steventsao.byot.share` and assign that group. The app already has it (see above). |
| Extension entitlements | `ShareExtension/BYOTShare.entitlements`: `com.apple.security.application-groups = [group.com.steventsao.byot]` |
| App Info.plist | `CFBundleURLTypes` gains the `byot-share` scheme (name `com.steventsao.byot.share`). No capability is needed for a URL scheme. |
| Other capabilities | None. The extension makes no network requests and doesn't read the Keychain. |

The extension saves what was shared into `ShareInbox/` in the App Group
container, then opens `byot-share://inbox?id=<uuid>`. The link carries only the
id, never the content. Share extensions have no public API to open their app,
so the extension calls `UIApplication.open(_:options:)` through the Objective-C
runtime (`BYOTShareViewController.openContainingApp`). This is a common
workaround, but App Review could object to it. If the call stops working in a
future iOS, the extension shows "Saved for byot" and the app offers the share
the next time it comes to the foreground. Shares nobody picks up are deleted
after two days.

The same release-script caveat applies: the command-line
`PRODUCT_BUNDLE_IDENTIFIER` override would also stamp `BYOTShare.appex` as
`com.steventsao.byot`. Remove that flag before archiving. Check that the
extension's version and build match the app's as well.

### Shipping without the share extension

1. In `project.yml`, delete the `- target: BYOTShare` entry under the `BYOT`
   target's `dependencies`.
2. Run `xcodegen generate`.

The app side stays harmless without the extension: the inbox is always empty,
so the picker never appears. The `byot-share` URL type can stay; opening it
just brings byot forward. If the widgets ship without the App Group too, the
app has no shared container, and the inbox is skipped entirely.

### What testers should check on device

- **Safari link.** Share a page to byot. byot opens a "Send to byot" sheet
  showing the link, with "New session" for each server and your recent
  sessions. Pick a recent session. The row shows progress while byot loads
  it, then the session opens with the link already in the message and the
  keyboard up. Nothing is sent until you tap Send. With the server offline,
  the sheet stays open and says so, so you can choose again.
- **Cancel in the share sheet.** Tap Cancel while byot is "Getting this
  ready". byot doesn't open and nothing is offered later.
- **Photos.** Share one or several photos (HEIC is fine; it arrives as JPEG).
  Pick "New session", choose a project, and tap Start session. The first
  message has the photos attached.
- **Files.** Share a PDF or a text file from Files. It is attached with its
  file name. Text shared from Notes goes into the message as text. Very long
  text (over about 12,000 characters) is attached as "Shared text.txt"
  instead.
- **Limits.** Share 10 photos plus a file from Files, or a file over 20 MB.
  The sheet's "Sharing" footer says what was left out and why. (The share
  sheet itself hides byot for more than 10 images or 10 files at once.)
- **An existing draft.** Start typing in a session, leave, then share into
  that session. The shared text is added after your draft, not over it.
- **Backing out.** Choose "New session", then go back without starting one.
  The next time byot comes to the foreground, it offers the share again.
  Cancel in the sheet discards it.
- **Accessibility.** At the largest text sizes, the attachment chips stack
  vertically. VoiceOver reads the sheet as "Sharing <summary>" and gives each
  destination a hint.
