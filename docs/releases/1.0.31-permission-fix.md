# BYOT 1.0.31 permission description correction

Candidate build: `20260929075519`. Based on the 1.0.31 release commit
`9bfc3bd17da023167a19896e9158e0691cdc29ce`.

Apple rejected build `20260927164049` under Guideline 5.1.1 on September 29,
2026 because the English camera, microphone and speech permission prompts
contained their Info.plist key names. The `InfoPlist.xcstrings` catalog omitted
English values. Xcode compiled English key names that overrode the valid base
Info.plist descriptions. Local-network access had the same defect.

Explicit English and Simplified Chinese descriptions now explain each use.
Camera access is for the user-selected pairing QR scanner, and voice access is
for the composer microphone. Neither is requested on ordinary app launch or
when typing. Photo attachments use PhotosPicker and do not require blanket
photo-library permission. Existing request timing is preserved.

The compiled-bundle regression checks all shipped permission localizations.
The release wrapper now rejects exported IPAs with missing or placeholder
permission text before upload. The gate reproduces the failure with the retained
1.0.31 IPA. Tests also cover an idle composer making no voice permission
requests and starting no audio recording.

Final validation and Apple submission identifiers are recorded in the companion
release receipt after verification.

## Validation

- 699 unit tests and 7 relevant UI tests passed on iPhone 17 / iOS 26.5;
  eight opt-in live-server tests were skipped. The real microphone prompt
  appears only after a tap, displays the English explanation, and denying
  access preserves the draft and allows continued typing.
- The scanner, dictation and image/document preview workflows passed. The
  simulator has no camera hardware; the compiled camera prompt is checked
  by the localization tests.
- A Release simulator build passed.
