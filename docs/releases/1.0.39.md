# BYOT 1.0.39 — The 1.0.37 branch merged back, and the first build with all of it

The App Store has been on 1.0.35 since 2026-10-19. Everything since then sat in two places that never met: `main` carried the 1.0.36 session-list change and the 1.0.38 usage-data corrections, while the unpushed branch `codex/testflight-feedback-20261027` carried the workspace-screen fix and the permission-string fix that TestFlight 1.0.37 was built from. 1.0.39 merges that branch onto `main` and is the first build containing all four. It goes to TestFlight and to App Store review.

## Why 1.0.39

1.0.38 (`20261102194112`) is already on TestFlight, built from `3219f20` before the merge, so it has the usage-data fixes but not the workspace or permission ones. A submission has to carry a build that has all of them, so the merge takes the next number rather than reusing 1.0.38. See [1.0.38](1.0.38.md) for that build, and [1.0.37](1.0.37.md), which arrives with the merge, for the build internal testers have been running since 2026-10-27.

## What changed since the live 1.0.35

The App Store build of 1.0.35 was archived from `390a78e`.

| Area | Change |
| --- | --- |
| Workspace loading (`OpenCodeWorkspaceStore.swift`) | `load()` treated a cancelled request as a failure, because `URLSession` throws `URLError(.cancelled)` rather than `CancellationError`. Leaving the projects screen or backgrounding the app mid-load cleared `compatibility` and left an error message behind. Cancellation is now recognised at both requests, and the previous summary is held until project loading finishes, so a cancelled load leaves the last known workspace state intact. From `60b88f8`. |
| Permission prompts (`Sources/Resources/InfoPlist.xcstrings`) | The catalog had only `zh-Hans` values, so the compiled English `InfoPlist.strings` carried no explanations and the camera, microphone, speech-recognition and local-network prompts could appear without their reason. English values are now explicit. **No permission keys were added or removed** — the same four keys as 1.0.35 — and a new test asserts every shipped language has a non-empty explanation for every `UsageDescription` key in the built Info.plist, and that the English value matches the base. From `25a87ad`. |
| Session list rows (`OpenCodeProjectSessionsView.swift`, `OpenCodeConnectedView.swift`, `OpenCodeSessionBrowserStore.swift`) | Rows said "Status unavailable" whenever a project had no status map, which also covered a saved list shown at launch and a project still loading. A sleeping tailnet computer can hold the first request for URLSession's default 60 s. Rows now say "Connecting" until the project answers, show no status while the offline notice is up, and keep "Status unavailable" for a server that answered with an error. Shipped to TestFlight as 1.0.36. |
| Usage data (`BYOTTelemetry.swift`, `BYOTTelemetryOpenCode.swift`) | The same `URLError(.cancelled)` confusion recorded every cancelled session-list fetch as `error_occurred(network, session_list)`, up to three per cancellation. Cancelled loads are no longer reported. Separately, a server negotiated before the person answered the usage-data question was marked reported even though the event was dropped, so an opt-in launch never sent `server_connected`; it is now held and sent on opt-in. Shipped to TestFlight as 1.0.38. |

The workspace fix and the usage-data fix are the same root cause. Releasing one without the other was the reason this merge happened before the submission rather than after.

## Validation

The whole `BYOTTests` target ran on the Mac mini (Xcode 26.5) on the existing iPhone 17 simulator "byot-baseline" (iOS 26.5), after the merge.

| Run | Result |
| --- | --- |
| `BYOTTests` | **778 tests: 770 passed, 8 skipped (live-server tests), 0 failed** — 663 swift-testing tests in 69 suites, plus 115 XCTest tests with 8 skipped. The merge added 9 swift-testing tests over 1.0.38's 654. |
| Merged tests specifically | `permissionPromptsAreReadable` passes, so every `UsageDescription` key in the built Info.plist has a non-empty explanation in both `en` and `zh-Hans`, with the English value matching the base — the regression that fix addresses. The branch's `OpenCodeWorkspaceStoreTests` additions pass. |
