# BYOT 1.0.42 — session names, prompt menu, haptics

Three small polish changes, and a build fix so `main` compiles on Xcode 26.3. It goes to TestFlight only.

## Why 1.0.42

1.0.41 (`20261111000630`) is on TestFlight, so this build takes the next number.

## What changed since 1.0.41

| Area | Change |
| --- | --- |
| Session names, `OpenCodeSubagents.swift`, `OpenCodeProjectSessionsView.swift`, `BYOTWidgetSync.swift`, `OpenCodeSessionView.swift` | OpenCode names a session `New session - <ISO 8601 time>` until the first reply. The session list, the widget and the Live Activity now show "New session" for that placeholder. A real title that only starts the same way is kept. |
| Prompt menu, `AgentMarkdownText.swift`, `OpenCodeSessionView.swift` | Long-pressing the words of a prompt opened the reply menu ("Copy response") and hid Undo and Fork, which sat on the bubble behind the text. The text's menu now takes its copy label and extra actions from the environment, so a prompt offers Copy prompt, Undo to this prompt and Fork before this prompt. |
| Haptics, `SharedUI.swift`, `OpenCodeSessionView.swift`, `OpenCodeSessionComposerView.swift` | A light tap on send, a warning buzz when a permission or question arrives, and a soft tap when a turn finishes. The last two fire only while the app is active with the session open. |
| Build, `OpenCodeSessionView.swift`, `OpenCodeSessionComposerView.swift`, `OpenCodeWorktreesView.swift` | On Xcode 26.3 these three `body` properties failed with "unable to type-check this expression in reasonable time". The session and composer bodies are each cut into three properties, and the Worktrees dialog titles are typed `LocalizedStringKey` properties. No behaviour change is intended. |
| Strings | One new string, "Copy prompt", with Simplified Chinese. |
| `Sources/Info.plist` | Unchanged, so no permission or privacy-label change. |

| `OpenCodePolishUITests` | All 15 passed. |

## Not covered

- The prompt menu and the haptics have no automated test and were not tried on a device before this build.
- The placeholder name was not looked at on screen; it is covered by unit tests only.
- The full `BYOTUITests` target was not run.
- `OpenCodeTerminalView`'s `body` still takes about 8.5 seconds to type-check on Xcode 26.3. It compiles, but it is the next one likely to fail.
