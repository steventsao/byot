# BYOT 1.0.41 — OpenCode 2 fixes from the backlog

This build fixes three open OpenCode 2 issues. It goes to TestFlight only.

## Why 1.0.41

1.0.40 (`20261102234628`) was approved and is `READY_FOR_SALE` on the App Store, so this build takes the next number.

## What changed since 1.0.40

From [steventsao/byot#124](https://github.com/steventsao/byot/pull/124).

| Area | Change |
| --- | --- |
| Idle marker ([#122](https://github.com/steventsao/byot/issues/122)), `OpenCodeV2Support.swift`, `OpenCodeV2EventReducer.swift` | OpenCode 2's `idle` history record marks the end of a turn. Before, it fell through to the generic case and became a text part, so every finished reply ended with "Idle". It is now dropped from the transcript, from both the message list and the event stream. |
| Worktree sessions ([#121](https://github.com/steventsao/byot/issues/121)), `OpenCodeV2Adapter.swift`, `OpenCodeSessionBrowserStore.swift` | `/api/project` can report an empty `sandboxes` list for a project that has Git worktrees. The project list now also reads the first page (100, newest first) of `/api/session` and adds each other directory its sessions use to that project's worktrees. If that request fails, the list falls back to `sandboxes` alone. A session listed from two directories is shown once. |
| Queue warning ([#107](https://github.com/steventsao/byot/issues/107)), `OpenCodeSessionStore.swift` | Removing the last paused queued prompt clears the "queued message is paused" warning. Before, an empty session turned into "Couldn't load this session". |
| Composer ([#115](https://github.com/steventsao/byot/issues/115)) | No app change. The clipping no longer reproduces. A new UI test checks that a multiline draft and its send button stay on screen after the keyboard closes. |
| Strings | No new strings. |
| `Sources/Info.plist` | Unchanged, so no permission or privacy-label change. |

## Backlog triage

The other open issues were checked and left alone:

- [#113](https://github.com/steventsao/byot/issues/113) (status truncated at accessibility sizes) is already fixed. The status moved out of the toolbar into a label with `fixedSize()`.
- [#98](https://github.com/steventsao/byot/issues/98), [#100](https://github.com/steventsao/byot/issues/100), [#92](https://github.com/steventsao/byot/issues/92), [#89](https://github.com/steventsao/byot/issues/89) and [#73](https://github.com/steventsao/byot/issues/73) are 1.0.31-era epics and features that have shipped (share extension, widgets and Live Activities, push).
