# BYOT 1.0.34 — OpenCode 2.0 and its pairing codes

OpenCode 2.0 shipped as `@opencode/cli` (2.0.32 on 2026-10-17), and byot could not connect to it: detection stopped with an unexpected content type. This release connects to 2.0 releases and reads OpenCode's own pairing codes (`opencode pair`, `opencode pair --remote`). It builds on the 1.0.33 source (`1389ba6`, `fix/testflight-feedback-october`).

## What changed

| Area | Change |
| --- | --- |
| Detection (`OpenCodeServerProtocol.swift`) | 2.0 releases answer `/global/health` with the web UI and return 404 for `/api/health`. byot now falls back to `server.info` (`/api/info`), which is what OpenCode's own app checks. A 401 there reads as a credentials error. |
| Pairing (`OpenCodeOneTimePairing.swift`, `OpenCodeServerSetupViews.swift`) | Scan, paste, or pick a photo of the `{"code","urls"}` QR code or an `/auth/connect/<code>` link. byot redeems the single-use code on every listed address at once (`GET /auth/connect/<code>`, `Accept: application/json`), keeps the earliest-listed address that answered after checking the token there with `/api/info`, and fills the form with user `opencode` and the 30-day token. Relay addresses are named "OpenCode remote". Spent or expired codes and unreachable addresses each get their own message. See [server-pairing.md](../features/server-pairing.md#opencode-2-pairing-opencode-pair). |
| Scan page copy | "Make a pairing code" now has an OpenCode 2 section (`opencode pair --remote`) above the OpenCode 1 helper script. |
| Rename (`OpenCodeSessionFeatures.swift`, `OpenCodeSessionFeatureService.swift`) | 2.0 renames with `PATCH /api/session/{id}` instead of `POST …/rename`. |
| Redo | 2.0 clears an undo with `DELETE …/revert` instead of `POST …/revert/clear`. |
| Slash commands (`OpenCodeComposerDispatch.swift`) | 2.0 requires the command under `name`, not `command`. |
| Form cancel (`OpenCodeActions.swift`, `OpenCodeV2Contract.swift`) | 2.0 cancels with `DELETE …/form/{formID}` instead of `POST …/cancel`. |
| Server files (`OpenCodeRemoteFiles.swift`) | 2.0 file responses carry only the directory in `location`, no project; byot still checks the directory. |
| Wrong password | The 401 message adds "If you paired with a code, scan a new one", since pairing tokens expire after 30 days. |
| Strings | Eight new or changed strings, each with Simplified Chinese. |
| Acceptance fixture (`scripts/e2e`) | Pinned to `@opencode/cli` 2.0.32 instead of beta 19271. Both npm packages link a bin called `opencode`, so the fixture runs each package's own binary. 2.0 health is read from `/api/info`. |

Every 2.0 route change is chosen from the server's published schema, so the betas keep using their routes.

## Not covered

- `opencode pair --remote` through the real opentunnel.xyz relay was not exercised end to end; the phone side is ordinary HTTPS to a publicly trusted certificate. The live fixture covers issuing and redeeming a real 2.0.32 code over HTTPS, the token signing in, and the code refusing a second use.
- The question API (`/api/question/request`) is gone in 2.0.32, so pending forms are listed per session rather than per location.
- Tokens are not renewed automatically. After 30 days the 401 message asks for a new code.
