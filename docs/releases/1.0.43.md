# BYOT 1.0.43 — follow a live turn until the reader scrolls back

One fix from TestFlight feedback. It goes to TestFlight and to App Store review.

## Why 1.0.43

1.0.42 (`20261113103624`) is on the App Store, so this build takes the next number.

## Feedback

| Feedback | Build | Report |
| --- | --- | --- |
| `ACcetZD227lYVBerP72GSVM`, 2026-11-22 | 1.0.42 | "Should auto anchor to bottom until user starts scrolling back to history". The screenshot shows a turn still working, with "Jump to latest" over its newest tool rows. |

## What changed since 1.0.42

| Area | Change |
| --- | --- |
| Following, `OpenCodeSessionView.swift`, `OpenCodeTranscriptParts.swift` | The transcript followed a turn only while the end of the conversation was within 32 pt of the screen's bottom, measured after each layout. A tool row or a long paragraph that grew the transcript by more than that before the scroll caught up counted as the reader scrolling away, so following stopped mid-turn and "Jump to latest" appeared. Following is now the reader's choice: on iOS 18 and later only a drag or flick that leaves the end turns it off, and the transcript catches up with every change in content height after layout. Scrolling back to the end, tapping "Jump to latest", opening the session or running a command turns it back on, and a scroll that comes to rest while following catches up with anything that arrived meanwhile. iOS 17 keeps the previous rule. |
| UI test fixture (DEBUG only) | `--live-turn`: a long conversation with a turn that streams reasoning, two shell commands and 70 paragraphs, a third of them long, one event every 400 ms. |
| Tests | `OpenCodeTranscriptPartTests.followsUntilReaderScrollsBack` covers the rules. `OpenCodePolishUITests.testLiveTurnFollowsUntilReaderScrollsBack` follows the live turn, scrolls back and checks the reader's place holds while output keeps arriving, then resumes with "Jump to latest" and follows to the end of the turn. Before the fix it failed at its first check: "Jump to latest" was up by the ninth paragraph. |
| Strings | None added or changed. |
| `Sources/Info.plist` | Unchanged, so no permission or privacy-label change. |

## Validation

Run on the Mac mini (Xcode 26.5) on an iPhone 17 Pro simulator, iOS 26.5.

| Run | Result |
| --- | --- |
| `testLiveTurnFollowsUntilReaderScrollsBack` on `main` before the fix | **Failed** at its first check: "The transcript should follow the reply". |
| `BYOTTests` with the fix | **796 tests: 788 passed, 8 skipped (live-server tests), 0 failed**: 679 swift-testing tests in 72 suites plus 117 XCTest tests. |
| `OpenCodePolishUITests` with the fix, twice | Every other test passed both times (30 runs). |
| `testLiveTurnFollowsUntilReaderScrollsBack` with the fix | Passed 3 of 3 runs. |

## Not covered

- Scrolling back to the end by hand is covered by the unit test only. In the UI test a swipe from the end stops inside the live turn, which is several screens tall, and the app's main thread then stays at 100% CPU in SwiftUI's lazy stack layout. The same happens with the old follow rule (an A/B run with the new rule switched off hung the same way, 60 s without going idle), so it is not from this change. It is listed as a known issue in the TestFlight notes and left for its own fix.
- iOS 17 keeps the old rule and was not run.
- The fix was not tried on a device before this build.
- The full `BYOTUITests` target was not run.
