# BYOT 1.0.31 — OpenCode parity and polish

This release closes the gaps found in the 2026-09-26 audit of 1.0.30 against current OpenCode: the server, the TUI and the web app. It is tracked by epic #98. It builds on the shipped 1.0.29 source (`95bc946`) and the App Store 1.0.29 metadata on `codex/testflight-loading-alignment` (`a4b35e6`).

**Status: ready to archive, not archived or uploaded.** The app source is commit `39aa9d5` on `claude/parity-1.0.31`. The commit that adds this file changes only release notes. `project.yml` sets `MARKETING_VERSION: 1.0.31`, and `scripts/asc-build-testflight.sh` defaults `BYOT_VERSION` to `1.0.31`.

## Known limitations

- **v2 servers.** Current v2 betas don't publish these routes, so byot hides the feature on v2:
  - diff review (`/api/vcs/diff`); per-turn and per-session diffs are v1 only
  - shell mode (`/api/session/{id}/shell`)
  - publishing a session
  - LSP and formatter status
  - server settings (`/global/config`)
- **Context meter on v2.** The v2 context window (`/api/session/{id}/context`) is fetched only when Details or Context and usage opens. The inline meter otherwise uses an estimate from the transcript.
- **AGENTS.md setup** sends the server's `init` command through the prompt queue. It is offered only when the command catalog lists `init`. It doesn't call `POST /session/{id}/init`, but upstream handles the two the same way.
- **Server settings.** Saving reloads every project on the server, which can interrupt agents that are working. The editor asks before saving for this reason. The older v1 `PATCH /config` is not used, because it writes a project `config.json` that OpenCode never reads.
- **Live Activities** are started and updated by the app, not by push. A turn that ends while byot is suspended is finished on the next status poll, about 15 seconds after byot runs again.
- **Share extension.** It opens byot through the Objective-C runtime, because extensions have no public API for this. App Review could object. If the call fails, the share is offered the next time byot comes to the foreground.
- **iPhone ⌘N.** On the shared simulator, the ⌘N UI test fails from the iPhone session list, as described above. Before distributing, check ⌘N and ⌘K on a device with a hardware keyboard. This is a P3 path, and the toolbar's compose button works.

## Prerequisites

1. **Signing.** Follow [1.0.31-signing.md](1.0.31-signing.md). The build now embeds two app extensions, and nothing has been registered yet. In the Apple Developer portal (team `449BD89VDV`), create the App Group `group.com.steventsao.byot` and the explicit App IDs `com.steventsao.byot.widgets` and `com.steventsao.byot.share`. Then enable App Groups with that group on those two IDs and on `com.steventsao.byot`.
2. **Release script bundle ID override.** `scripts/asc-build-testflight.sh` passes `--xcodebuild-flag=PRODUCT_BUNDLE_IDENTIFIER="$BYOT_BUNDLE_ID"` to the archive. Xcode applies that setting to every target, which stamps both extensions `com.steventsao.byot`, so the archive or App Store validation fails. Before archiving with the extensions, delete that one line from `archive_flags`. `project.yml` already sets each target's bundle ID, and the script's check that the archive is `com.steventsao.byot` still passes. This branch leaves the release script unchanged.

### Shipping without the extensions

Use this if the portal setup isn't done yet. The app works without the extensions: it hides the Live Activities switch and never shows the share picker.

1. In `project.yml`, delete `- target: BYOTWidgets` and `- target: BYOTShare` from the `BYOT` target's `dependencies`. The targets themselves can stay.
2. In `Sources/BYOT.entitlements`, remove the `com.apple.security.application-groups` key.
3. In `asc/testflight-notes.md`, remove the Live Activity/widgets line and the "Share a link, photo or file" line.
4. The script runs `xcodegen generate` itself. The bundle ID override is harmless when no extension is embedded.

To ship only one extension, keep its dependency, the App Group entitlement and its line in the notes, and still apply prerequisite 2.

## Release command

From the root of a checkout of `claude/parity-1.0.31`, on the release Mac with `asc` authenticated and the signing keychain available:

```bash
BYOT_VERSION=1.0.31 BYOT_UPLOAD_TESTFLIGHT=1 ASC_APP_ID=6782403920 scripts/asc-build-testflight.sh
```

The script:

1. Stamps 1.0.31 with a 14-digit build number.
2. Archives, exports `.asc/artifacts/BYOT.ipa`, checks the version, build and bundle ID, and runs `asc xcode validate`.
3. Publishes to the **Internal Testers** group with `asc/testflight-notes.md` as the en-US What to Test notes.

It doesn't submit for beta review unless `BYOT_SUBMIT_BETA_REVIEW=1` is set.

To build and validate without uploading, leave out `BYOT_UPLOAD_TESTFLIGHT=1 ASC_APP_ID=6782403920`. The version and build of each embedded extension must match the app's. Check them in the archive:

```bash
for x in BYOTWidgets BYOTShare; do
  plutil -p ".asc/artifacts/BYOT.xcarchive/Products/Applications/byot.app/PlugIns/$x.appex/Info.plist" \
    | grep -E '"CFBundle(Identifier|ShortVersionString|Version)"'
done
```

If the SwiftPM cache stalls on the release Mac, as it did for 1.0.28, add `BYOT_ISOLATE_SWIFTPM_CACHE=1`. SwiftTerm is a new package dependency in this release.

After distribution, record the receipts under `docs/releases/1.0.31/` as in earlier releases: the publish receipt, the build and beta state, group membership, the notes, and the signature. Then update the epic's Release checklist.
